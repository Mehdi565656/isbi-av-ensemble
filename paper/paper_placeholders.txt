SECTION 2.4  Morpho-U-Net -- where operators enter / structuring elements
======================================================================
REPLACE:
  \PH{State precisely where these enter the network: as additional input
  channels (pre-processing) or as a refinement of the predicted map
  (post-processing), and give the structuring-element size(s).}

WITH:
  Both transforms are applied as a \emph{parameter-free pre-processing
  block} ({\tt MorphoPreprocessor}) before any learned layers. The raw
  RGB input $\mathbf{x}\!\in\!\mathbb{R}^{3\times H\times W}$ is first
  smoothed with a $5\!\times\!5$ Gaussian ($\sigma\!=\!1.0$) per channel
  (via depth-wise convolution with a fixed, non-learned kernel). The
  \emph{white top-hat} subtracts a morphological opening (erosion then
  dilation, $3\!\times\!3$ structuring element) from the smoothed image,
  isolating small bright features. The \emph{distance transform} is
  approximated by $10$ successive erosions (same $3\!\times\!3$
  structuring element) accumulated and normalised, encoding each vessel
  pixel's proximity to the background. Both transforms are applied
  depth-wise, producing three top-hat channels and three distance
  channels; these are concatenated with the original RGB to form a
  $9$-channel input tensor $[\mathbf{x},\,\mathrm{TH}(\mathbf{x}),\,
  \mathrm{DT}(\mathbf{x})]\!\in\!\mathbb{R}^{9\times H\times W}$ that is
  fed to the first encoder convolution. No parameters are added

SOURCE: MorphoPreprocessor.__init__() and forward() in
morpho/Morpho_Unet_TopHat_DistanceTransform_Fixed592.ipynb:
  gauss_kernel=5, gauss_sigma=1.0, morph_kernel=3, threshold=0.47,
  dist_iters=10
  White top-hat = blurred - opening(blurred)
  Distance transform = sum of 10 iterative erosions / 10
  MorphoUNet concatenates [x, tophat, dist] -> 9 channels -> inc(enc_in=9)

SECTION 3.1  Implementation Details -- full block
======================================================================
REPLACE:
  implemented in \PH{framework} and trained with \PH{optimizer}
  (learning rate \PH{lr}, batch size \PH{bs}) for up to \PH{epochs} epochs;
  the BiFPN-UNet (64--1024ch) was trained for $300$ epochs. The loss is
  \PH{loss, e.g.\ cross-entropy / Dice / their sum}, and training used
  \PH{hardware}.

WITH:
  implemented in PyTorch and trained on a single NVIDIA Quadro RTX 8000
  (48\,GB VRAM). All BiFPN and Morpho variants use AdamW
  (lr\,$=5\!\times\!10^{-4}$, weight decay $2\!\times\!10^{-4}$) with a
  cosine-annealing schedule ($\eta_{\min}\!=\!10^{-5}$), batch size $4$,
  and up to $150$ epochs ($300$ for BiFPN-UNet 64--1024ch); the standard
  U-Net baseline uses Adam (lr\,$=10^{-3}$, no schedule, batch size $2$,
  fixed $150$ epochs). The loss for BiFPN and Morpho variants is a
  weighted sum of class-weighted cross-entropy and soft Dice over the
  vessel classes:
  $\mathcal{L} = 0.7\,\mathcal{L}_{\mathrm{CE}} +
  0.3\,\mathcal{L}_{\mathrm{Dice}}$;
  the U-Net baseline uses class-weighted cross-entropy only. Class weights
  are computed from training-set pixel frequencies and normalised by the
  mean vessel-class inverse frequency. For BiFPN and Morpho variants,
  early stopping terminates training if the test-set vessel Dice does not
  improve over $10$ consecutive evaluation checkpoints ($50$ epochs;
  $100$ epochs for the 300-epoch run)

SOURCE (BiFPN / Morpho variants): BiFPN_Unet_Fixed592.ipynb cell 23,
Morpho_Unet_TopHat_DistanceTransform_Fixed592.ipynb training cell:
  optimizer = AdamW(lr=5e-4, weight_decay=2e-4)
  scheduler = CosineAnnealingLR(T_max=EPOCHS, eta_min=1e-5)
  BATCH_SIZE = 4, EPOCHS = 150 (300 for 64-1024ch run)
  loss = CEDiceLoss(dice_weight=0.3)
  PATIENCE_EVALS = 10 (eval_every=5 epochs => 50 epochs patience)
  PATIENCE_EVALS = 20 for the 300-epoch run (=> 100 epochs patience)

SOURCE (Standard U-Net): Unet_images_only.ipynb cell 28:
  optimizer = Adam(lr=1e-3, betas=(0.9,0.999), eps=1e-7)
  no scheduler
  BATCH_SIZE = 2, EPOCHS = 150 (fixed, no early stopping)
  loss = CrossEntropyLoss(weight=class_weights) only

SOURCE (hardware): nvidia-smi -q:
  Product Name: Quadro RTX 8000 (x2, single GPU used per run)
